# 認知モデル — コードリーディングの4つの能力

> この章では、本教材が目標とする4つの能力の全体像を理解します。演習を始める前に必ず読んでください。

---

## なぜ「全部読もう」とすると失敗するのか

現代のソフトウェアは、単一の人間が全容を把握できる規模をはるかに超えています。たとえば `django/django` は数十万行、`linux/linux` は数千万行に達します。

すべての実装を逐一追跡しようとすると、**短期記憶の容量（マジカルナンバー7±2）** がすぐに枯渇し、「読んだはずなのに何もわからない」状態に陥ります。

コードリーディングは、この認知的制約を前提として設計された**戦略的な解析作業**です。

---

## 4つの能力の全体像

```
[コードベース]
     │
     ▼
┌─────────────────────────────────────────────┐
│  Ⅰ. 抽象化の信頼                            │
│  インターフェースと責務だけを把握し、         │
│  内部をブラックボックスとして信頼する         │
└────────────────┬────────────────────────────┘
                 │ 全体像のメンタルモデルが形成される
                 ▼
┌─────────────────────────────────────────────┐
│  Ⅱ. 目的駆動の探索                           │
│  工学的タスクを宣言し、関係ない領域を         │
│  意図的に「読まない」判断をしながら進む       │
└────────────────┬────────────────────────────┘
                 │ 目的地に近い箇所に到達する
                 ▼
        （判断が分岐する）
        ┌────────┴────────┐
        │                 │
   インターフェースで   インターフェースだけでは
   解決できる          解決できない（★漏れ）
        │                 │
   そのまま進む         ▼
                ┌────────────────────────────┐
                │  Ⅲ. 抽象の漏れへの対応     │
                │  必要な箇所だけ内部実装に  │
                │  踏み込み、深く解読する    │
                └────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────────┐
│  Ⅳ. 視点の切り替え（メタスキル）             │
│  上記Ⅰ〜Ⅲを状況に応じて柔軟に切り替える    │
│  俯瞰↔詳細を意図的にコントロールする        │
└─────────────────────────────────────────────┘
```

## 各能力の詳細

### 能力Ⅰ：抽象化の信頼

**本質**: 「このモジュールが何をするか」を理解する。「どのようにするか」は問わない。

確認すべき情報：
- 関数のシグネチャ（引数の型・名前・返り値）
- モジュールの `README` や `docstring`
- 公開されているインターフェース（`export` / `public` なもの）

**読まなくていい情報**（この能力の段階では）：
- 関数の内部ロジック
- プライベートなヘルパー関数
- 内部データ構造の実装

> 🔑 **原則**: インターフェースが明確ならば、内部の実装を知らなくてもそのモジュールを「使える」し「理解できる」。

---

### 能力Ⅱ：目的駆動の探索

**本質**: コードを読む前に「なぜ読むのか」を言語化する。

すべての読書セッションは以下の宣言から始まります：

```
目的：[例] リクエストがルートに到達するまでの処理を追いたい
仮説：[例] app.js → Router → middleware → handler の順だと思う
除外：[例] データベース接続部分・テストコードは今回は読まない
```

目的が明確であれば、コードは「読む / 飛ばす」の2種類に分類できます。**飛ばす判断は怠慢ではなく、認知資源の合理的な配分です。**

---

### 能力Ⅲ：抽象の漏れへの対応

**本質**: 「内部を読む必要があるか」という判断そのものを訓練する。

内部実装に踏み込む必要がある典型的な状況：

| 状況 | 具体例 |
|---|---|
| パフォーマンス問題 | ORMが生成するSQLを確認したい |
| セキュリティ調査 | サニタイズ関数の実装に抜け穴がないか確認したい |
| 低レイヤーの挙動 | タイムアウト処理がネットワーク層でどう動くか |
| ドキュメントと挙動の乖離 | 「仕様に書いてないエラー」が発生している |

> ⚠️ **注意**: 漏れが起きていると判断した場合のみ内部に潜る。  
> 「念のため」で潜り始めると、認知負荷が爆発する。

---

### 能力Ⅳ：視点の切り替え（メタスキル）

**本質**: Ⅰ〜Ⅲを状況に応じて手動でコントロールする意識を持つこと。

実際のコードリーディングは線形ではありません。熟練者は以下のように視点を往復させます：

```
俯瞰（全体構造把握）
  └→ 中間（モジュール間の関係把握）
       └→ 詳細（特定関数の内部実装）
            └→ 中間（得た情報を全体像に統合）
                 └→ 俯瞰（更新されたメンタルモデルで次を選択）
                       ...
```

この往復を意識的に行えるようになることが、この教材の最終目標です。

---

## まとめ

| 能力 | 問い | 答え |
|---|---|---|
| Ⅰ 抽象化の信頼 | 何を読むべきか？ | インターフェースだけ |
| Ⅱ 目的駆動の探索 | なぜ読むのか？ | 宣言した目的のためだけ |
| Ⅲ 抽象の漏れへの対応 | どこまで深く読むか？ | 漏れが起きている最小の箇所だけ |
| Ⅳ 視点の切り替え | どう使い分けるか？ | 状況を判断して意図的に選択する |

次は [`how_to_use.md`](./how_to_use.md) で演習の具体的な進め方を確認してください。
