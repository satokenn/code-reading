# 演習の進め方

> この教材の演習は「正解を探すテスト」ではありません。**判断のプロセスを言語化する訓練**です。

---

## 演習の3ステップ

すべての演習は以下の3ステップで行います。

```
STEP 1: 目的宣言（演習前）
    ↓
STEP 2: 探索（演習中）
    ↓
STEP 3: 振り返り（演習後）
```

各ステップを飛ばすと、演習の効果が大幅に下がります。特に**STEP 3を省略すると訓練にならない**ので注意してください。

---

## STEP 1：目的宣言

演習ファイルを開いたら、問題文を読む前に以下のフォーマットを自分のメモに書いてください。

```
【目的宣言】
---
🎯 目的：
（例：Expressのリクエストがどのミドルウェアを通過するかを追いたい）

📍 仮説（どこを読めば分かると思うか）：
（例：app.use() の実装と、Router クラスの中にあると思う）

🚫 除外（今回は読まない領域）：
（例：データベース処理・テストコード・エラーハンドリング）
---
```

> **なぜこのステップが必要か**  
> 目的がなければ「何が重要か」の判断基準が存在しない。目的宣言によって、「読む」「飛ばす」の判断が初めて可能になる。

---

## STEP 2：探索

問題を読んで、実際にOSSリポジトリを調べます。以下のルールに従ってください。

### ✅ やること

- 問いに答えるために必要最小限の箇所を読む
- 読んだ箇所・飛ばした箇所をメモに記録する
- わからない単語は `reference/glossary.md` を参照する

### ❌ やらないこと

- ヒントを見る前に解答を開く
- 「念のため」で関係ない箇所を読む
- 問いに答えることなく次の問いに進む

### 時間の目安（各演習ファイル）

| フェーズ | 所要時間の目安 |
|---|---|
| 目的宣言の記入 | 5分 |
| ウォームアップ問題（3〜5問） | 15〜30分 |
| フロー追跡・設計意図問題 | 30〜60分 |
| 振り返り | 10分 |
| **合計** | **約60〜100分** |

---

## STEP 3：振り返り

演習が終わったら以下の問いに自分の言葉で答えてください。

```
【振り返り】
---
① 「読まなかった」判断は正しかったか？
   （飛ばした箇所が実は重要だったことはあったか？）

② 予想（仮説）と実際に違ったことはあったか？

③ 次回どう変えるか？
   （目的宣言の精度・除外設定・探索ルートなど）
---
```

この振り返りを繰り返すことで、「どこに注目すべきか」の直感が育ちます。

---

## 解答ファイルの使い方

各Chapterの演習ファイルと解答ファイルは**別ディレクトリに分離されています**。

```
curriculum/01_abstraction_trust/
├── ex01_interface_only.md   ← 問題（ここから始める）
├── ex02_module_contract.md
├── ex03_trust_test.md
└── answers/                 ← 全問解き終えてから開く
    ├── ex01_answers.md
    ├── ex02_answers.md
    └── ex03_answers.md
```

**ルール:**
- `answers/` フォルダは、**その演習の問いをすべて自力で解いてから**開く
- 解答は「正解」ではなく「解答例」。自分の答えと視点の違いを比較に使う
- 詰まったときは答えを見る前に10～15分考え続けること

## 使用するリポジトリの準備

各演習に入る前に、対象のリポジトリをローカルにクローンしておくことを推奨します。

```bash
# 入門：express
git clone https://github.com/expressjs/express.git

# 中級：flask
git clone https://github.com/pallets/flask.git

# 上級：django
git clone https://github.com/django/django.git
```

ローカルにクローンすることで、`grep`, `fd`, `git log` などのCLIツールを活用できます（`reference/cheatsheet.md` 参照）。
